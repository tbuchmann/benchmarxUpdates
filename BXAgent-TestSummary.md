# BXAgent Test Coverage Summary

Test counts per example, broken down by category, for the `BXAgent*` tool
implementations only (the only tool with concurrent sync enabled across these
examples). Generated by running each module's full suite fresh:

```
./mvnw -pl examples/<ex>/Benchmarx<Name> -am test -Dbenchmarx.tool=BXAgent<Name>
```

"Monotonic" combines `MonotonicCreating` + `MonotonicDeleting`. Counts are test
*methods*, not classes (some examples split Batch Bwd across several classes, e.g.
pdb1topdb2's `BatchBackwardFirst`/`NotFirst`/`Fixed`).

## 2026-08-07: `performAndPropagateEdit` now calls `sync()` everywhere — RESOLVED

Until this update, `asttodag`, `gantttocpm`, `settooset`, and `pntopnw`'s BXAgent
adapters called the forward-only `transform()` inside `performAndPropagateEdit` instead
of `sync()` (see `BXAgent-KnownIssues.md` #2, `BXAgent-KnownIssues-Fixes.md` Fix 1). All
four were switched to call `sync()` (adding the missing `SyncConflictPolicy` import
where needed, and passing both `Options` and, for gantttocpm/settooset, the required
forward/backward `PostProcessor` hooks). The other four adapters (bag1tobag2,
pdb1topdb2, familiestopersons, ecoretosql) already called `sync()` correctly.

Applying that adapter fix alone (Fix 1) initially surfaced two real generator-level
bugs as concrete regressions:

1. **Deletion-cascade gap** (`BXAgent-KnownIssues-Fixes.md` Fix 2): `sync()`'s generated
   code had no deletion-cascade handling, so deleted objects were resurrected during
   concurrent sync. Affected `ast2dag`, `gantt2cpm`, `pn2pnw`, `set2oset` specifically —
   not `bags12bags2`, `pdb12pdb2`, `families2persons`, `ecore2sql`, which already
   handled deletion in `sync()` correctly.
2. **Creation-propagation gap, `ast2dag` only**: source-side creations weren't reaching
   the target during concurrent `sync()` (e.g. adding a `BestDigit` subtree left the DAG
   at its pre-edit state). Distinct from the deletion-cascade gap — found only in
   `ast2dag`'s generated `sync()`.

Both were fixed upstream in the `bxagent` generator repo. **All regressions are
resolved.** The two `@Disabled` reproduction tests added on 2026-08-05
(`NonMonotonic.testConcurrentSourceDeleteHelpersTargetChangeModelDuration` in
gantttocpm, `Conflicts.testConcurrentDeleteASrcFullRenameTrgConflict` in settooset) were
re-enabled without changing their assertions and pass.
